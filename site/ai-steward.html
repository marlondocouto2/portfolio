Project 5 · AI agent

An AI agent that maintains a forecasting model

Every week, new FX data arrives and the production margin model from Project 3 may no longer be the best choice. Here an AI agent does the weekly review a data scientist would do: it diagnoses what changed, backtests and tunes challengers within a budget, and recommends keep or switch in a pull request. Plain Python computes every number, enforces the rules and checks the memo. A human merges.

What is the promotion rule?

The gate a challenger must pass before it can replace the champion. The agent can recommend a switch, but only this rule can approve it.

  1. The last 8 weeks are hidden. All week, the agent's tools score models on the 26 weeks before that. It never sees how any model did in the most recent 8 weeks.
  2. One test a week. The agent picks its best challenger and runs promote once. That scores the champion and the challenger on the hidden 8 weeks, so a challenger can't win just by being tuned to the data the agent was looking at.
  3. Three checks, all required:
    • Big enough: at least 1% lower error than the champion. Smaller gains aren't worth changing the production model.
    • Not luck: a Diebold–Mariano test compares the two models' daily errors and asks how likely a gap this size would be if they were really equally good. That chance must be under 10% (p < 0.10).
    • Honest risk band: the challenger's 5% margin-at-risk band (from Project 3) must be breached on 2–9% of days, close to the 5% it promises.

In the chart above, solid bars are what happened with the rule. Hatched bars show what would have happened if every challenger the method proposed had been switched in without the rule.

Methods

The guardrails

The agent decides what to try and why. Everything below is plain Python it can't change.

1Config space4 model families, 6 feature groups, 4 training windows, 2 refit frequencies, 3 EWMA half-lives, hyperparameters within fixed ranges. Nothing else can be deployed.
2Hidden windowModel errors from the last 8 weeks are hidden. Development tools score only the 26 weeks before them.
3Budget15 backtests, 2 tuning runs and 1 promotion test a week, enforced by the tools.
4Promotion ruleOn the hidden window, a challenger needs at least 1% lower error, a one-sided Diebold–Mariano p-value below 0.10, and a 5% risk band breached on 2–9% of days (explained above).
5Memo checksEvery number must match a cited ledger value, "better/worse" must match the sign, and a switch needs a passed test. After 3 failed tries the week is escalated and the champion stays.
6Pull requestThe agent proposes; CI checks it only touched the champion, reports and data; a human merges.

What the results show

  • A strong model is hard to beat, and blind automation makes it worse. Starting from Project 3's tuned XGBoost, the scripted playbook and Optuna found a challenger that looked better in development nearly every week. Accepted without the rule, those challengers would have raised error over the following 12 weeks by 1.07% and 0.35%.
  • The agent held back when there was nothing to gain. On 16 sampled weeks it kept the strong champion every time and used about 6 of its 15 backtests. On the same weeks, the baselines proposed 24 challengers, and 15 of them would have done worse.
  • With a weak champion, the agent found the most. Starting from stage 1 only, it cut error by 2.34%, against 1.60% and 1.48% for the baselines, with about half their backtests. It built lean models on the markup and lagged-residual features, the inputs Project 3's SHAP analysis ranked highest. It made only 4 switches, so read this as promising, not proven.
  • The promotion rule has a cost. The same 8-week test that protected the strong champion blocked most real gains for the weak one: accepting every proposal would have cut error by 6–7%. An adaptive rule, with a longer window or a sequential test, is the next step.

How it works

  1. Tools as a command-line interface (python -m steward ...): status, data summary, champion report, diagnose, backtest, tune, promote, submit. Each result goes into a ledger with an id.
  2. Four "brains" use the same tools, budget and rule: never retrain, a scripted playbook, Optuna over the whole config space, and the AI agent: Claude Code running headless with written instructions.
  3. Replay: each Friday from January 2024 to August 2026 is replayed from the same starting champion. The agent works in a sandbox whose data stops at the cutoff, so it can't see the future.
  4. Scoring: each week's chosen model is deployed at the cutoff and scored on the following 12 weeks, which no tool could see.
  5. Cost: $0. The agent runs on an existing Claude plan, without an API bill.
